# 16 与 24 MPI三种线性求解方案对比

## 1. 测试条件与统计口径

|        | 设置                                                    |
| ------ | ----------------------------------------------------- |
| 测试算例   | 14个结构有限元算例                                            |
| 并行配置   | `16 MPI × 1线程`、`24 MPI × 1线程`                         |
| 线程设置   | 每个MPI进程使用1个计算线程，BLAS采用单线程配置                           |
| 全局直接法  | 通过PETSc接口调用MUMPS完成全局直接求解                              |
| BDDC   | 沿用各算例已验证的Krylov方法与BDDC配置，最大迭代数为200                    |
| 无预条件迭代 | 与对应BDDC算例采用相同的Krylov方法和收敛阈值，不设置预条件器，最大迭代数为5000        |
| 残差检验   | 使用原总体矩阵计算显式相对残差$\lVert b-Ax\rVert_2/\lVert b\rVert_2$ |
| 时间口径   | 总时间覆盖完整作业；求解阶段从总体矩阵装配结束计时至位移恢复结束                      |
| 内存口径   | 以约0.3秒的间隔采集全部MPI进程RSS，峰值取包含全部进程的有效采样最大值               |

## 4. 结论

1. **线性方程组求解精度。** 以PETSc + MUMPS求解结果为基准，对BDDC求解结果的显式相对残差进行对比。`50w-2d`、`50w-2d-pload`、`Pshear_17w_cquad4_Pload2`和`Pshell_17w_cquad4_Pload2`的直接法残差为$10^{-5}$至$10^{-6}$量级，BDDC在16 MPI和24 MPI下的残差均与直接法同阶且数值更低。`10w-mix12d-mpcnested`在24 MPI下的BDDC残差为$9.803\times10^{-8}$，较直接法高约26.5倍，但仍低于$10^{-7}$。其余9个算例的BDDC残差均不高于$9.928\times10^{-9}$。BDDC在14个算例上均达到有效求解精度。无预条件迭代仅在`50w-mix02d-allrbe2`上收敛，其余13个算例均未得到可验收的最终解。

2. **求解时间。** 从16 MPI增加至24 MPI后，PETSc + MUMPS和BDDC均有13个算例的作业总时间缩短。24 MPI下，PETSc + MUMPS在11个算例上的总时间短于BDDC；BDDC仅在`10w-3d`、`10w-mix013d`和`Pshell_17w_cquad4_Pload2`上更快。`50w-mix02d-allrbe2`是唯一随MPI进程数增加而变慢的算例，其PETSc + MUMPS求解阶段不足0.4秒、BDDC求解阶段不足2.3秒，而总时间为224.254～337.103秒，主要成本位于求解前的强约束数据处理。

3. **内存占用。** PETSc + MUMPS从16 MPI增加至24 MPI后，14个算例的作业峰值RSS全部增加；BDDC有13个算例增加，仅`YUANTONG_10w_Cweld_SOL101`由57.926 GiB降至55.514 GiB。24 MPI下，BDDC只在`10w-3d`、`10w-mix013d`、`50w-2d-allF_M_P`和`50w-mix23d`四个算例上的峰值RSS低于PETSc + MUMPS，其余10个算例更高。

4. **rank内存均衡性。** BDDC在大型混合维算例上的rank内存差异最明显。`50w-mix23d`、`100w-mix23d-rbe`和`100w-mix23d`的最大/最小比在16 MPI下为6.215～6.913，在24 MPI下为5.465～5.574；PETSc + MUMPS对应范围分别为2.235～2.510和1.856～2.865。`50w-2d`和`50w-2d-pload`的BDDC最大/最小比由约2.46降至约2.25，表明增加子域数降低了最重rank的RSS，但未消除rank间差异。

## 5. 矩阵装配与约束处理方式对比

### 5.1 SGSim现有实现

1. 分区数据库将单元集合$\mathcal E_r$分配给MPI rank $r$。单元分区决定各rank负责计算的单元，不决定全局矩阵的行所有权。
2. `AssemblyEigen`完成全局方程编号和SPC、RBE、MPC约束展开。若单元物理自由度满足$u_e=T_eq$，则单元刚度贡献为
   $$
   A_e=T_e^{\mathsf T}K_eT_e.
   $$
3. `Algebra`创建全局分布式稀疏矩阵$A$。PETSc按连续行区间分配矩阵所有权，每个rank只保存其负责的矩阵行和相应非零元。
4. 各rank逐单元累加$A_e$。本rank拥有的矩阵行直接写入本地存储，其他条目通过MPI发送至相应行的所有者。最终得到
   $$
   A=\sum_r\sum_{e\in\mathcal E_r}T_e^{\mathsf T}K_eT_e.
   $$
5. 每个rank持有的是全局矩阵$A$的连续行块$A[I_r,:]$，而不是本rank物理单元形成的局部刚度矩阵。

### 5.2 MFEM的实现

MFEM在并行网格上区分局部自由度和真实自由度。每个rank先将所属单元装配为局部自由度矩阵$A_r^{\mathrm{loc}}$，再由延拓矩阵$P$将全局真实自由度映射到各rank的局部自由度。全局矩阵通过并行三重乘积形成：
$$
A=P^{\mathsf T}\operatorname{diag}\!\left(A_1^{\mathrm{loc}},\ldots,A_P^{\mathrm{loc}}\right)P.
$$
其中，$P$同时描述共享自由度复制和非协调网格悬挂自由度插值。Dirichlet边界条件在`FormLinearSystem`阶段按真实自由度消去。`ParBilinearForm::ParallelAssemble`生成真实自由度上的并行矩阵，同时保留局部矩阵和局部—真实自由度映射。

除完全装配外，MFEM还提供单元装配、部分装配和无矩阵模式。部分装配保留积分点数据，通过局部算子直接计算矩阵作用，避免形成完整稀疏矩阵，是其GPU执行路径的基础。

### 5.3 SGSim现有方式的优点与局限

**优点**

1. **结构约束处理完整。** SPC、RBE2、RBE3、一般MPC和嵌套约束统一展开到最终独立方程。
2. **全局矩阵分布式存储。** 完整矩阵不在rank 0集中保存，降低了单个进程的内存压力。
3. **单元计算并行。** 各rank独立计算所属单元，PETSc完成跨rank矩阵条目的传输与合并。

**局限**

1. **局部物理算子未保留。** 单元贡献并入全局矩阵后，矩阵行块不再对应物理子域，区域分解方法需要重新收集单元贡献并构造局部算子。
2. **代数负载与物理分区脱节。** 各rank行数接近不能保证非零元数量、装配通信量和求解负载均衡。
3. **宽约束增加通信与填充。** RBE3和一般MPC可能连接多个远端主自由度，增加跨rank写入、矩阵非零元和后续分解填充。
4. **GPU装配效率受限。** 逐单元、细粒度的非规则稀疏写入不利于GPU批量执行，需要采用局部算子、批量装配或部分装配路径。

### 5.4 一种组织方式

我们可以采用MFEM的分层组织思想，同时保留现有的结构约束处理。统一数据路径为
$$
K_e\longrightarrow\widehat K_r\longrightarrow K_r\longrightarrow A.
$$
1. **构造局部物理算子。** 各rank将所属单元刚度矩阵直接累加为未施加约束的局部物理刚度矩阵：
   $$
   \widehat K_r=\sum_{e\in\mathcal E_r}L_e^{\mathsf T}K_eL_e.
   $$
   单元贡献写入$\widehat K_r$后立即释放，不长期保存全部$K_e$。

2. **构造局部约束映射。** 设$q$为全局最终独立方程，$R_r$提取本rank涉及的方程$q_r=R_rq$，$T_r$将$q_r$展开为本rank物理自由度：
   $$
   u_r=T_rq_r=T_rR_rq.
   $$
   $T_r$由`AssemblyEigen`已经完成的SPC、RBE2、RBE3、一般MPC和嵌套约束展开构造。跨rank主自由度作为$q_r$中的共享项，由$R_r$负责通信，无需改变物理单元分区。

3. **构造约束后的局部算子。** 每个rank独立计算
   $$
   K_r=T_r^{\mathsf T}\widehat K_rT_r.
   $$
   $K_r$及$R_r$作为区域分解、局部平滑和接口分析的统一输入。

4. **按求解路径生成算子。** 需要显式全局矩阵时，统一装配
   $$
   A=\sum_rR_r^{\mathsf T}K_rR_r.
   $$
   全局直接法使用$A$；BDDC由$K_r$和$R_r$直接创建`MATIS`；GPU迭代路径可直接计算$R_r^{\mathsf T}T_r^{\mathsf T}\widehat K_rT_rR_rq$，避免显式形成$A$。

### 5.5 下一步工作计划

1. **降低局部子问题的求解成本。** 当前BDDC的局部子问题采用双精度直接法求解，数值稳定性较好，但局部分解产生的填充和因子存储占用较多内存。下一步将研究低精度直接分解和迭代局部求解方法，重点评估其对峰值内存、计算时间、外层迭代次数和求解精度的影响。

2. **开展多节点大规模算例验证。** 区域分解方法的并行优势主要体现在多节点、大规模计算场景。下一步将把现有BDDC算法集成到`SGPetsc`中，并在浪潮服务器上开展更大规模算例测试，重点考察多节点并行效率、通信开销、峰值内存、负载均衡性和可扩展性。

3. **改进网格划分与负载均衡。** 当前部分算例存在子域规模、接口自由度和局部计算量分布不均衡的问题。下一步将研究面向区域分解求解的网格划分方法，在保证子域物理连通性的基础上，综合考虑单元计算量、接口规模、复杂约束分布和局部分解成本，提高各MPI进程之间的计算与内存均衡性。

4. **探索适用于复杂约束问题的AMG方法。** 当前尚未系统开展AMG方法验证。一方面，现有AMG配置在部分结构力学问题上缺乏足够的稳定性；另一方面，RBE和MPC等复杂约束改变了物理自由度与最终独立方程之间的映射关系，难以直接构造有效的近零空间和粗空间。下一步将研究约束感知的近零空间构造、物理自由度聚合和粗层算子生成方法，并通过现有算例验证其稳定性、内存占用和并行效率。
