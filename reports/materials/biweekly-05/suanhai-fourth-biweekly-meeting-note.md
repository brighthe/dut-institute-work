# Suanhai | Meeting | 大连理工项目第四次双周会议纪要

- **文档状态**：整理稿，待参会各方核对
- **整理日期**：2026 年 9 月 20 日
- **会议性质**：项目第四次对外双周技术讨论
- **整理依据**：2026 年 9 月 18 日会议逐字稿
- **整理原则**：区分已完成验证、现场讨论形成的阶段性判断、待双方确认事项和后续行动，不将探索性结论写成最终方案

## 一、会议信息

- **会议主题**：异构并行验证 Demo、性能收益与后续协同研发讨论
- **会议时间**：2026 年 9 月 18 日 19:45:57—21:04:31
- **会议形式**：线上会议
- **参会人员**：李宁宁、田昊伦、宋维豪、魏华祎、胡凯、杜阳、陈玉震

## 二、会议目标

1. 汇报近两周基于 SGSim 数据库开展的异构并行验证 Demo。
2. 讨论张量后端切换、单元计算和 GPU 路径的当前验证效果及限制。
3. 明确性能对比、工程化改造、两套代码协同和 `matrix-free` 的后续问题。
4. 协调 PETSc 预条件子工作与异构并行工作的推进关系。

## 三、阶段进展汇报

### 3.1 异构并行验证 Demo

宋维豪汇报了基于 SGSim 数据库和新架构思路制作的验证型 Demo。当前 Demo 主要完成以下工作：

1. 支持从 SGSim 的 HDF5/DB 文件读取数据，也保留与数据库直接交互的路径。
2. 在 `Prepare` 层对不同类型数据库数据进行统一整理，便于后续计算使用。
3. 将整理后的数据转换为张量数据结构，并通过 `xtensor` 或 `torch` 切换计算后端。
4. 目前 `xtensor` 路径用于 CPU 验证，`torch` 路径具备 CPU/GPU 后端扩展条件。
5. Demo 已完成单元计算、全局矩阵装配、线性求解和结果输出的最小流程验证，但尚未接入 SGSim 正式的 PETSc 求解流程，也尚未完成多进程、多线程和完整工程集成。

### 3.2 正确性与初步性能观察

1. 在约 18,000 个节点、96,000 个四面体单元的自构造梁模型上，Demo 完成了单进程、单线程求解验证。
2. 以直接法结果作为对照，三个计算后端得到的结果总体能够保持正确性。
3. 采用 Jacobi 预条件的迭代求解约 556 步达到停止条件。会议指出，预条件残差和真实相对残差的停止口径不同，当前结果不能简单按同一个容差数值直接比较。
4. 在另一组较大规模测试中，SGSim 原迭代路径约耗时 20 秒，张量计算路径约耗时 12 秒，现场将其作为“可能存在性能收益”的初步观察；该结果尚未形成正式报告，也未完成统一环境、重复测试和内存统计，不能作为最终性能结论。
5. 当前张量路径存在通过预计算和中间数据换取计算效率的特点。会议认为应结合显存容量设计分批计算、数据驻留和调度策略，而不是单纯追求降低内存占用。

### 3.3 当前技术限制

1. 当前测试规模较小，且仅使用单进程、单线程，尚未充分体现 GPU 并行能力。
2. 当前矩阵求解仍未使用 GPU 版 PETSc，部分计算在 GPU/CPU 之间发生回迁，可能造成额外内存占用和数据搬运开销。
3. 当前内存统计主要针对 CPU 主存，显存占用尚未独立插桩确认；现场对内存峰值增加原因仍未形成最终解释。
4. `xtensor` 当前主要用于 CPU，`torch` 虽具备 GPU 后端条件，但完整 GPU 求解链路尚未打通。
5. 雅可比逆等部分计算仍采用循环填充，后续可结合 BLAS 等基础库优化。
6. 直接读取 DB/HDF5 文件与数据库交互的效率差异已有初步观察，但仍需在统一数据规模和重复测试下确认。

## 四、主要讨论与阶段性共识

### 4.1 Demo 当前定位

会议认为，当前 Demo 的首要目标是验证技术路线是否能够走通，包括数据导入、单元计算、张量后端切换、矩阵装配和结果正确性。当前阶段不宜过早据此评价完整 GPU 方案的最终性能。

后续需要补充至少一组有说服力的对比结果，说明采用新架构后在性能、后端切换灵活性或数据组织方面能够带来的实际收益，为是否继续扩大改造范围提供依据。

### 4.2 两套代码路线的协同

当前形成了两条工作路径：

- 继续维护并运行 SGSim 原有代码，用于结果对照和工程基线；
- 在独立架构/Demo 路径中验证新的张量化和异构计算方案。

会议认为，原有 SGSim 代码可以作为新架构的正确性参照和验证脚手架，但不要求两套实现立即合并为同一套代码。后续需要进一步讨论长期维护方式、结果对照机制以及何时由合作方决定保留、替换或逐步弱化原有路径。

### 4.3 `matrix-free` 的定位

会议讨论认为，`matrix-free` 可能同时服务于两个目标：

1. 避免显式存储规模很大的整体矩阵，降低内存压力；
2. 使更多计算和数据驻留在 GPU 上，减少矩阵组装及 CPU/GPU 数据搬运。

对于高阶单元、特殊高阶形函数或子结构型密集计算，`matrix-free` 可能具有更明显的价值；对于低阶单元，其 GPU 性能收益需要结合计算密度和数据搬运成本具体评估。合作方目前尚未明确最终业务场景，算海团队将在架构层预留显式矩阵、单元矩阵和 `matrix-free` 等可切换路径，具体应用范围后续结合场景继续确认。

### 4.4 PETSc、BDDC 与异构并行的关系

合作方询问了 PETSc 预条件子手册和 BDDC 接入进展。胡凯说明，当前主要困难不是算法本身，而是 SGSim 现有装配方式与区域分解所需数据组织方式存在差异：

- 区域分解需要获得每个 `rank` 或子域上的局部刚度矩阵；
- 还需要明确局部自由度排序与全局自由度之间的映射；
- 当前 SGSim 更接近直接生成全局装配贡献，尚未以区域分解所需形式提供局部矩阵和相关结构信息；
- 因此，BDDC 及相关预条件子接入仍需进一步理解源码、确认接口或补充装配路径。

会议形成的阶段性意见是：性能调优/迭代法路线和异构并行路线可以同步推进。PETSc、预条件子和区域分解工作可继续作为性能专项独立推进，同时评估其与新异构架构共享局部矩阵、分区和自由度映射信息的可能性。双方需要先把数据接口和代码边界沟通清楚，避免重复实现。

### 4.5 后续工程化工作量与维护成本

合作方提出，当前 Demo 路线如果继续工程化，有限元内核、抽象接口和 CUDA 后端的实现工作量可能较大，需要提前评估：

1. 从验证型 Demo 发展到可交付架构需要改造哪些模块；
2. 新旧两套代码并行期间如何避免功能漂移和重复维护；
3. 架构实现与具体功能实现如何解耦，以便双方分工协作；
4. 单元计算、装配、求解器和数据库访问之间的接口是否能够长期稳定。

## 五、会议结论

1. 当前异构并行 Demo 已经走通从 SGSim 数据读取、数据整理、张量后端切换、单元计算、矩阵装配到线性求解的最小验证路径。
2. Demo 已证明新架构具备进一步验证的可行性，但现阶段测试规模、并行度和 GPU 求解链路不足以支撑最终性能结论。
3. 月底前应补充一组统一环境下、可复现且有说服力的性能对比，重点说明性能收益来源和适用条件。
4. CPU 主存与 GPU 显存必须分开统计；当前张量路径内存峰值增加的原因仍需通过插桩和资源释放检查进一步确认。
5. `matrix-free` 作为异构架构的可选计算路径继续保留，重点结合高阶单元、特殊形函数和内存受限场景评估其价值。
6. PETSc/BDDC 性能调优与异构并行工作保持并行推进；局部刚度矩阵、自由度映射和分区信息应作为双方后续协作的重点接口。
7. 新架构暂不要求立即替换 SGSim 原有实现，原有代码继续作为基线和正确性参照；两套代码的长期维护和合并策略需后续共同决策。
8. 下一轮双周会议因国庆假期原则上顺延，具体时间由双方另行协商，期间重要进展继续在项目群中同步。

## 六、后续行动项

后续工作按三个方向推进。稳定的 GPU 测试环境作为异构并行 Demo 的支撑条件，不单独列为一条主线。

### 6.1 异构并行方案与 Demo

- **责任人**：宋维豪、魏华祎。
- **主要任务**：进一步优化和完善异构并行方案 Demo，补充统一环境下的重复测试、后端切换说明、性能对比、内存与显存统计，以及数据组织和运行流程说明。
- **协作重点**：通过可复现的 Demo 和对比结果，帮助大连理工方评估方案的技术可行性、性能收益、适用条件和后续工程化改造工作量。
- **环境支撑**：协调稳定的 GPU 测试环境，包括 GPU 节点、编译配置、依赖版本、访问方式和运行规范，用于支撑 Demo 的持续验证和性能评估。
- **阶段产出**：完善后的 Demo、运行说明、统一口径的对比数据和适用边界说明。

### 6.2 迭代法性能基线与求解器优化

- **责任人**：胡凯、杜阳。
- **工作依据**：大连理工方已将性能基线工作概括为“性能摸底及瓶颈点”，并提出围绕**单元计算、约束处理、分区、分布式向量/矩阵、数据库**五个方向开展后续优化。胡凯需要重点关注这五个方向，并形成对应的测试、分析和推进动作。
- **主要任务**：继续推进 PETSc、预条件子和区域分解相关的迭代法性能基线工作，同时将求解器性能问题与上述五个方向关联起来分析，避免只从迭代次数或求解器耗时单独判断瓶颈。
- **重点分析内容**：
  1. **单元计算**：确认不同单元类型的计算成本、数据访问和局部矩阵生成对整体求解时间的影响。
  2. **约束处理**：分析 SPC、MPC、RBE 等约束处理对矩阵性质、局部问题规模、通信和收敛性的影响。
  3. **分区**：分析网格、单元、自由度和约束关系的划分方式，以及分区不均对局部求解、内存和负载均衡的影响。
  4. **分布式向量/矩阵**：核对局部刚度矩阵、分布式矩阵和向量的装配、数据所有权、通信、同步及局部—全局映射。
  5. **数据库**：分析 `DBManager`/数据库读取、数据组织和数据搬运对求解准备阶段及后续异构计算的影响。
- **协作重点**：胡凯负责算法、求解器、预条件子和五个优化方向的技术跟踪；杜阳结合对 SGSim 源码和现有流程的熟悉程度，协助确认接口、装配流程、计时位置和代码实现细节。双方需要加强源码理解、接口定位、算例测试和结果分析方面的沟通，逐项形成问题清单和后续动作。
- **阶段产出**：可复现的测试环境、求解配置或使用手册、典型算例测试结果，以及围绕五个优化方向形成的瓶颈分析、优先级和下一步验证计划。

### 6.3 网格分区与任务划分

- **责任人**：陈康。
- **主要任务**：启动网格分区和任务划分方向的初步方案讨论，分析现有分区策略对单元计算、约束处理、局部矩阵构造、通信开销和负载均衡的影响。
- **讨论重点**：下一次讨论先明确问题定义、已有数据、评价指标和初步研究路线，再决定是否开展典型算例上的分区对比测试。
- **衔接关系**：后续需要进一步分析该方向与异构并行、迭代求解和负载均衡工作的接口关系，为后续协同研发提供基础。
- **阶段产出**：网格分区与任务划分问题清单、初步方案和后续验证计划。
