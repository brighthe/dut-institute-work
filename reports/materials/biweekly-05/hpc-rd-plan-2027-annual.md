# 2027 年度异构并行研发计划

## 年度研发安排

### 01 第一季度｜3 月底：架构边界与核心接口设计

明确新路线与 SGSim 原有 CPU/MPI 流程的关系，确定数据接入、网格与自由度、分布式对象、算子、张量、执行上下文、内存管理和后端注册等接口；同步确定首期支持范围，搭建最小 CPU 骨架。

**里程碑**：完成第一版架构设计、接口说明和支持范围清单，跑通数据读取—算子调用—结果导出的最小路径。

### 02 第一至第二季度｜6 月底：独立有限元内核与 CPU 参考闭环

面向限定范围的典型算例，实现网格、函数空间、自由度映射、约束处理、`matrix-free` 算子、局部计算、贡献归约、求解调用和结果组织，与 SGSim 原有 CPU 结果进行正确性对照。

**里程碑**：独立新路线完成最小 CPU 闭环，形成参考实现、校核结果和问题清单。

### 03 第二至第三季度｜9 月底：CPU/CUDA 多后端与单节点验证

在 CPU 参考闭环稳定后，完善后端注册、能力查询、设备选择、执行上下文、Kernel 派发、主机与设备内存管理、数据传输和同步机制，接入 NVIDIA CUDA 后端。

**里程碑**：形成支持 CPU/CUDA 切换的单节点原型，完成正确性、内存占用、传输和分阶段性能对比。

### 04 第三至第四季度｜12 月中旬：分布式异构执行与规模验证

完善分布式向量/张量、`Ownership/Halo` 和 MPI 通信适配，验证共享自由度贡献归约、rank/GPU 绑定、多 rank、多 GPU 及具备条件时的多节点运行。

**里程碑**：形成分布式异构执行原型，明确验证规模、性能收益和适用边界。

### 05 第四季度｜12 月底：工程化整理与年度交付

依据前期验证结果完善支持范围，整理构建部署、运行配置、错误诊断、回归测试、结果对照和使用说明；保留 SGSim 原有 CPU/MPI 路径作为兼容路线和结果基线。

**里程碑**：交付年度候选版本、配套文档、验证报告和验收材料。

## 计划边界与推进原则

**先验证，再扩展**：2027 年优先完成限定单元、材料、载荷和约束范围内的可验证路线，不把全部 SGSim 功能覆盖、所有复杂约束和更多后端列为年度必达项。

**两条路线并行保留**：SGSim 原有 CPU/MPI 流程继续作为稳定兼容路线和结果基线；新增异构路线独立演进，依据正确性、内存、通信和端到端性能证据逐步推进工程化。

架构与接口 → CPU 参考闭环 → CUDA 单节点 → 分布式验证 → 工程化交付
