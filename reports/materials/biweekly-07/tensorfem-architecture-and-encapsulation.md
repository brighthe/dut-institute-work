# TensorFem 异构并行架构：认识、验证与设计建议

## 原始文件

- 原件：[TensorFem架构与封装改造.html](TensorFem架构与封装改造.html)（12 页网页幻灯片，页脚标「TensorFem · 架构讨论稿」；`origin_date` 取原件内嵌的生成时间 2026-10-28，原件自注依据为「当前本地源码与设计讨论；本次未运行求解器或新增性能结论」）

## 核心内容与结论

1. **架构认识与目标能力**（第 1–2 页）
   - 架构认识：在统一的有限元数据与计算框架下，通过后端适配调用不同计算库，通过分区与通信组织多进程协作。示意图从 SGSim 入口经输入 Adapter 解释 `DBManager` 数据，由 Analysis Driver 编排步骤，有限元核心（Mesh、FunctionSpace、约束与状态、有限元算子）经统一张量操作接口与代数与求解接口调用 xtensor / Torch 与 PETSc 适配，分区与分布负责归属、交换与归约，结果经结果 Adapter 回写 SGSim；原有 FEM 分支保留为兼容与结果基线。原件标注为「目标架构认识示意；具体边界待共同确认」。
   - 四项目标能力及核验方式：后端可替换（同一问题的结果与接口行为）、分布可演进（不同分区与进程配置的一致性）、资源可管理（主机内存、显存及阶段成本）、功能可扩展（扩展位置、依赖和回归结果）。
2. **Demo 现状与三个问题**（第 3–6 页）
   - 现状：SGSim 运行入口可选择原有或 TensorFem 分支；单进程直接使用已有 Service，多进程经 `Partition` 取得本 rank 的分区数据；后端支持 XTensor CPU 与 Torch CPU / GPU，单元为 Hex8 / Tet4，经 PETSc 装配与求解后恢复位移、反力与中心应力并写回。分区输入中节点与 SPC 仍有全局读取，结果仍存在完整向量汇集。
   - 问题①：COO 行列编号由 CPU 循环逐项生成，可参考按轴广播再展平的统一表达；两种实现的执行成本与存储占用须实测，不能直接等同评价。
   - 问题②：已有 `NumericalBackend` 统一入口，但 XTensor 与 Torch 两条路径在数据与形状、矩阵与几何、积分与内部求解、展平与贡献写入各环节的实现方式不同，操作规则与底层库函数复用仍需逐项对齐。
   - 问题③：分析层（Analysis / DistributedStaticAnalysis）仍直接处理原生 Tensor 访问、格式转换、同步与 PETSc 交接；分析步骤与存储、转换、传输、同步、PETSc 交接的边界划分由正式架构评审确定。
3. **风险与改造重点**（第 7–8 页）
   - 三类风险：数据与计算职责不清导致迁移中的语义偏差；后端接口不一致带来替换成本与行为差异；全量复制、COO 存储、通信与硬件容量使规模与运行成本受限。对应措施分别为围绕数据关系设计并用源 ID、位移、反力和应力校核，统一封装并优先复用后端库函数，以及分别测量 RSS、显存、传输和通信后按实测瓶颈调整。
   - 改造方向：输入与结果交接改为 Adapter；网格、自由度与约束明确为 Mesh / FunctionSpace / 约束职责；张量计算与求解交接明确后端函数封装与代数交接边界；分区与多进程以现有实现为基础，结合网格与空间调整。首轮 Mesh、FunctionSpace 与分区的必要实现列为建议项，实现量待评估。
4. **推进计划、验证安排与待确认事项**（第 9–12 页）
   - 分四阶段推进：架构骨架 → 核心接口 → 重要功能 → 扩展验证，每阶段以交付与校核结果决定继续或调整范围；前置条件为代码访问与评审人员、可重复构建环境、代表算例及 CPU/GPU 硬件与运行权限。
   - 初步验证覆盖 CPU/GPU 后端替换、多进程符合新数据组织、实现遵循正式架构三项，具体算例、误差阈值与配置在实施评估和架构评审后确定。
   - 下个双周交付目标（原件标「已确认交付方向」）：形成内部达成一致、且有初步验证结果的正式架构，交付物为正式架构文档、关键接口与骨架代码、初步验证结果、评审结论与未决清单。
   - 需与老师共同确认四项：架构认识与目标能力、统一张量接口的边界（含数据持有与释放责任）、基础模块与 `Partition` 的调整、首轮实施与验收范围。
