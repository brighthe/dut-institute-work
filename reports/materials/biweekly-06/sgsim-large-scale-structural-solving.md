# SGSim 大规模结构求解测试：网格分区、直接法与 BDDC

## 原始文件

- 原件：[SGSim_大规模结构求解.html](SGSim_大规模结构求解.html)

## 核心内容与结论

1. **大规模圆筒模型规模与测试环境**（第 1–2 页）
   - 模型组成：四边形壳单元 `CQUAD4`（$1,805,376$ 个）与焊接连接单元 `CWELD`；总体矩阵阶数 $11,364,102$，总体非零元数 $574,955,912$；实值物理模型，采用复数双精度运算（PETSc 64 位索引、MKL LP64）。
   - 硬件与并行配置：4 个计算节点（`compute222`、`223`、`225` 各约 $754\text{ GiB}$ 物理内存，`compute231` 约 $991\text{ GiB}$）；32 进程布局为每节点 8 个，128 进程布局为每节点 32 个；每进程单线程（`OMP`、`MKL`、`OpenBLAS` 均设为 1）。
   - 软件与调度：同一部署版本的 SGFEM、Algebra 与 PETSc 3.22.1、MUMPS，运行于共享文件系统 BeeGFS 与 Slurm 调度系统。
2. **原始图分区与圆筒几何分区策略对比**（第 3–5 页）
   - 两种方案使用相同有限元模型，仅改变单元的分区归属，保留单元类型与连接定义（注：原件第 3–4 页引用的 `assets/cylinder-partitions/` 6 张分区视图为外部相对路径，未随单文件内嵌）。
   - **原始图分区**：采用原 Partition 通用图划分流程，以单元负载均衡为目标；部分区域包含空间分离的片段（128 分区中仅 64 个分区为单连通块，其余包含多个连通块）。
   - **调整后的几何分区**：沿筒长方向分段、沿圆周方向分区，结合 `CWELD` 焊接连接成组并做连通性修复；32 分区按轴向 $4\text{ 段} \times \text{周向 } 8\text{ 区}$ 组织（每区 $54,936\text{–}57,904$ 个壳单元，最大值/均值 $= 1.026$），128 分区按轴向 $8\text{ 段} \times \text{周向 } 16\text{ 区}$ 组织（每区 $13,336\text{–}14,772$ 个壳单元，最大值/均值 $= 1.047$，按共享节点与 `CWELD` 核验 128 个分区全部为单连通块）。
3. **32 进程直接法（`PREONLY + 全局 LU + MUMPS`）分区对比**（第 6–7 页）
   - 四节点共 32 个 MPI 进程、单线程下对比两种分区：

   | 指标 | 原始图分区 | 几何分区（$4 \times 8$） |
   | --- | --- | --- |
   | 程序总耗时 / s | 1,201.913 | 1,060.666 |
   | 线性求解相关流程耗时（`Get RHS` 至 `solve Fini`）/ s | 1,016 | 876 |
   | 刚度计算 / 运行开始至组装完成 / 组装至求解起点 / s | 35 / 116 / 14 | 36 / 113 / 14 |
   | MUMPS 分解有效内存合计 / MB（$10^6$ 字节） | 245,360 | 251,333 |
   | 最大单进程分解有效内存 / MB | 17,876 | 12,289 |
   | 分解运算量估计 / FLOP | $7.55211 \times 10^{13}$ | $7.58813 \times 10^{13}$ |
   | 实际最大前沿矩阵阶数 | 25,523 | 27,108 |
   | 求解后真实相对残差 $\|b - Ax\|_2 / \|b\|_2$ | — | $1.894 \times 10^{-13}$ |

   - **结论与边界**：几何分区使程序总耗时减少 $141.247\text{ s}$（$11.8\%$），求解相关流程缩短 $140\text{ s}$（$13.8\%$），最大单进程分解有效内存下降 $31.3\%$；但分解有效内存合计增加 $2.4\%$、FLOP 估计基本不变，耗时下降不能归结为总体分解内存或运算量减少，编号、消元排序及并行任务分配的具体贡献尚未分别验证。
4. **128 进程求解方法对比：`GMRES + BDDC` vs `全局 LU + MUMPS`**（第 8–9 页）
   - 两组复用同一 $8 \times 16$ 圆筒几何分区与四节点 128 进程布局。
   - **BDDC 子域与代数粗层结构**：128 个子域各含 $85,278\text{–}95,160$ 个自由度，接口自由度为 $2,544\text{–}3,396$；子域间整体校正由 $14,033$ 阶中间粗系统承担（16 个 MPI 进程参与），再建立 $384$ 阶最终粗系统由 MUMPS 直接求解（`levels = 1`，细层与中间粗层均开启角点、边平均与 Deluxe，关闭面平均）。
   - **完整流程对比**：

   | 指标 | GMRES + BDDC | 全局 LU + MUMPS |
   | --- | --- | --- |
   | 程序总耗时 / s | **828.271** | 1,578.468 |
   | 真实相对残差 $\|b - Ax\|_2 / \|b\|_2$ | $8.486 \times 10^{-9}$ | $4.173 \times 10^{-13}$ |
   | Krylov 迭代次数（`restart = 100`，`rtol = 1e-8`） | 142 | 不适用 |
   | 各进程 RSS 内存峰值之和 / GiB | 612.83 | 689.34 |
   | 最大 / 最小单进程内存峰值 / GiB | 4.95 / 4.58 | 8.23 / 4.56 |

   - **结论**：相同 128 分区下，BDDC 达到 $10^{-8}$ 相对残差目标，总耗时较直接法减少 $750.197\text{ s}$（降低 $47.5\%$），各进程内存峰值之和降低 $11.1\%$，最大单进程内存峰值由 $8.23\text{ GiB}$ 降至 $4.95\text{ GiB}$（两组并非相同最终精度）。
5. **大规模算例总结与适用边界**（第 10 页）
   - 分区调整显著影响 32 进程直接法的求解开销；128 进程下 BDDC 在达到 $10^{-8}$ 目标残差时总体时间与内存开销均低于直接法；几何分区直接法在 128 进程下总耗时（$1,578.468\text{ s}$）高于 32 进程（$1,060.666\text{ s}$）。
   - 各组均为单次测量，确认稳定加速幅度与阶段成因仍需重复测试和更细的阶段计时。
6. **补充验证：中小规模算例一层与两层物理划分对照**（第 11–12 页及弹窗，2026-10-17 记录）

   | --- | --- | --- | --- | --- | --- | --- |
   | **10w-3d**（16 MPI · CG） | 一层 | 54 | 是 | 约 $7.72 \times 10^{-9}$ | 11.40 | 8.41 |
   | **10w-3d**（16 MPI · CG） | 两层（$16 \times 4$） | 203 | 是 | 约 $9.25 \times 10^{-9}$ | 16.05 | 7.94 |
   | **100w-mix23d**（24 MPI · CG） | 一层 | 110 | 是 | $9.138 \times 10^{-9}$ | 214.81 | 43.93 |
   | **100w-mix23d**（24 MPI · CG） | 两层 | 500 | 否 | $3.203 \times 10^{-2}$ | 396.69 | 35.99 |
   | **100w-mix23d-rbe**（24 MPI · CG） | 一层 | 110 | 是 | $8.890 \times 10^{-9}$ | 217.24 | 43.86 |
   | **100w-mix23d-rbe**（24 MPI · CG） | 两层 | 500 | 否 | $1.000$ | 379.72 | 37.06 |
   | **Pshell_17w_cquad4_Pload2**（24 MPI · GMRES） | 一层 | 100 | 是* | $6.148 \times 10^{-6}$ | 73.86 | 26.18 |
   | **Pshell_17w_cquad4_Pload2**（24 MPI · GMRES） | 两层 | 48 | 是* | $4.350 \times 10^{-6}$ | 35.87 | 26.81 |

   - *注*：`Pshell` 两组满足 KSP 内部判据，但真实相对残差约为 $10^{-6}$；未收敛运行仅记录停止前的采样峰值，不解释为完整求解的内存优势。
7. **混合模型的分区与求解配置调整及 RBE 事件耗时**（第 13–14、18 页及弹窗，2026-10-16 记录）
   - 针对两个混合模型两层划分未收敛问题，同时更换第一层单元归属、重组区域内子域，并将外层方法由 CG 改为 `FGMRES`（右预条件、`restart = 100`；RBE 细层开启角点、面平均、Deluxe，中间粗层开启角点、边平均、面平均、关闭 Deluxe）：
     - `100w-mix23d`（$24 \times 6 = 144$ 子域）：`FGMRES` 221 步收敛，真实相对残差约 $9.836 \times 10^{-9}$，外部墙钟时间 **$164.77\text{ s}$**，总 RSS 峰值 **$38.90\text{ GiB}$**。
     - `100w-mix23d-rbe`（$24 \times 8 = 192$ 子域）：`FGMRES` 198 步收敛，真实相对残差 $9.152 \times 10^{-9}$，外部墙钟时间 **$153.23\text{ s}$**，总 RSS 峰值 **$39.35\text{ GiB}$**。
   - **RBE 198 步运行 PETSc 事件耗时（Time Max）**：`KSPSolve` $106.99\text{ s}$、`PCSetUp` $24.16\text{ s}$、符号/数值分解 $0.66 / 11.20\text{ s}$（6 次调用）、`PCBDDCSchr` $13.39\text{ s}$；细层预条件应用中 Dirichlet 求解 $48.37\text{ s}$（396 次，Ratio 5.9）、Neumann 求解 $26.87\text{ s}$（198 次，Ratio 2.9）、粗问题求解 $15.78\text{ s}$（198 次，Ratio 18.6），嵌套 `MatSolve` $75.40\text{ s}$。局部预条件应用累计耗时高于数值分解。
8. **`10w-3d-mpc-1st` 两层划分与 `Pshear` 零主元故障定位**（第 15–17 页及弹窗）
   - **`10w-3d-mpc-1st`**（16 MPI，两层划分）：第一层按负载均衡重划 16 个 MPI 区域（每区单元数范围从 $176\text{–}36,184$ 收窄至 $11,658\text{–}13,485$），第二层在区域内按单元属性分组并要求共享节点邻接图连通（共 65 个子域：第 0 区 5 个，其余各 4 个）；CG 85 步收敛，真实相对残差 $7.238 \times 10^{-9}$，全流程耗时 $13.51\text{ s}$，峰值总 RSS $8.92\text{ GiB}$。
   - **`Pshear_17w_cquad4_Pload2`**（$166,852$ 个 `CSHEAR` + $334,521$ 个 `CBAR`，共 $501,373$ 个单元，32 MPI）：将二级划分从按属性分组改为在 MPI 区域内按非零元权重统一划分并保持连通（128 子域接口节点数从 $167,670$ 降至 $10,751$）；但无论重新划分 32 个区域还是保留原有 32 个区域，**均在进入 CG 前的粗层 Deluxe 界面块 $H_F = \sum_s S_F^{(s)}$ 内部稠密 LU 分解中出现零主元（`GETRF info=3`）而失败**。局部 Neumann 奇异的 `MUMPS ICNTL(24)=1` 与 `deluxe_zerorows=1` 不作用于该内部 LAPACK 块，后续需保存失败界面块数值与索引以核验界面零能模式、约束关系与块构造一致性。
