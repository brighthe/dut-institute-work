# SGSim 代码迁入 GitLab：仓库访问与源码可见性

本文只记录 SGSim 各仓库与子模块的访问权限范围，以及由此决定的源码可见性边界。

「可读」指当前开发环境中存在可读源码；「不可访问」指仓库路径不可达。其余子模块的空目录属正常交付状态，其接口由 Artifact 的公开头文件和预编译库补足。本文的分类不涉及甲方源代码仓库中是否保存了相应实现。

## 仓库访问与源码可见性（2026-08-21 SuanHai fork 之后）

研究院于 2026-08-21 将部分项目 fork 到 `SuanHai` 分组。实际机制是主仓 `.gitmodules` 中 13 个子模块**改写了 3 条 URL**，其余 10 条仍指向原命名空间。前后对比：

| 对象 | fork 之前 | 现在 |
| --- | --- | --- |
| 主仓 `SGSim` | 只读 | **可写**（SuanHai fork） |
| `Artifact` | 只读 | **可写** |
| `Algebra` | 不可访问 | **可读可写**（新增） |
| `DBManager` | 不可访问 | **可读可写**（新增） |
| `Partition` | 不可访问 | **可读可写**（新增） |
| 其余 10 个子模块 | 不可访问 | 不可访问（不变） |
| `ThirdParty` | 只读 | **失去** |

三个新增模块与《模块权限开放申请及评审》的结论一致，暂缓申请的模块未开放。写权限经 `git push --dry-run` 实测确认（五个仓均返回 `* [new branch]`，未实际创建分支）；该命令不发送 pack，pre-receive 钩子不执行，因此只证明**项目级写权限**，未验证 `dev` 的分支保护与 MR 规则。

原命名空间已全面撤权，旧路径均返回 “could not be found or you don't have permission to view it”，因此迁移是强制的，不是可选优化。

三个新开放模块的源码**尚未通读核验**：源码可读不等于存在可供外部模块调用的稳定接口，涉及分区数据、局部矩阵和局部—全局映射的可获取性需读源码后判定。

## 分组规范的覆盖范围

`SuanHai` 分组 README 只规定**获取代码**：主线分支为 `dev`、递归克隆子模块、克隆后将各子模块重置为干净状态。**它不包含提交规范、分支命名约定、MR 流程或分支保护说明。**这与《模块权限开放申请及评审》中「先按最小必要权限开通提交和 Pull Request 权限；分支保护、评审人和合并规则确认后执行」对应——提交侧的规范尚未落地，**待研究院明确**。在此之前按通用做法执行：从 `dev` 拉功能分支开发，经 MR 合并，不直接推 `dev`。

该 README 自身仍将 `ThirdParty` 指向原命名空间，而原命名空间已撤权，照 README 流程克隆会在该步失败。这佐证了 `ThirdParty` 的失访属撤权连带影响，而非有意安排。

README 的克隆流程会使各子模块处于 detached HEAD（记录的是主仓指针，而非分支顶端），且规范未涉及后续开发环节。因此向三个新开放模块提交改动前，需自行切回分支，否则提交不挂任何分支。操作见 [build-and-run.md](build-and-run.md)。

## 分支

SuanHai 分组下的 `SGSim` 远端只有一个分支 `dev`，即主线。

本机当前工作分支为 `suanhai-dev`（`e05c7be`），跟踪 SuanHai 远端的 `dev`。

三个开放子模块各自是独立仓库，分支与主仓互不相干，远端同样只有 `dev`：

| 子模块 | 提交 | 本机状态 |
| --- | --- | --- |
| `Algebra` | `d22338f` | 分支 `dev`，跟踪 `origin/dev` |
| `DBManager` | `21e6b04` | detached HEAD |
| `Partition` | `e85858a` | detached HEAD |

子模块由 `git submodule update` 按主仓记录的 SHA 检出，默认即为 detached HEAD；向子模块提交改动前需先切回 `dev`。

克隆与构建的操作影响见 [environment.md](environment.md) 3.2 与 2.3，时间线见 [log.md](log.md)，任务状态见 [plan.md](plan.md)。
