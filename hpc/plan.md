### 2. 性能专项

> 定位（2026-07-20 杜阳老师口径）：最大目的是**熟悉代码**；运行算例中发现内存爆炸、性能慢等问题向大工反馈即可，由大工与浪潮沟通解决（没发现问题也没关系）。

- [ ] **预条件子设计（紧迫）**：对方已有 Hypre、PETSc KSP 的代码测试算例，但目前不收敛；需我们设计预条件子确保收敛性。
  - 2026-08-04：PETSc KSP 已在本机源码构建走通最小闭环（`build/petsc-minimal`，`TPetscKsp<Real_t>` 收敛），为本项提供本机可复现的 KSP 试验环境，见 [build-and-run.md](build-and-run.md) 8.2。
- [x] **PETSc 最小验证闭环已走通**（2026-07-28，宋维豪）。曾因 Artifact 缺 `libmkl_avx2.so.2`、`libmkl_def.so.2` 退出计算，根因是研究院本地开发机部署了 oneAPI，重新拉取仓库后解决（对口武兴创）。
- [x] **Hypre 最小计算流程已走通**（2026-07-31）：研究院发布最新版本后，团队已完成编译并走通计算流程。这标志着版本获取、编译和最小计算流程的可用性阻塞已闭合，**不代表性能基线、规模测试或调优已经完成**。
  - **历史过程**：研究院侧在早版本已完成集成但运行可能有问题；杜阳 2026-07-28 表示将提交新版本，算海团队 2026-07-29 17:23 仍反馈缺少 hypre 头文件，2026-07-30 获告知最新版本已发布并可开始测试。
- [ ] **抽取性能基线（研究院建议的下一步）**：2026-07-28 李宁宁部长建议着手抽取性能基线，作为后续性能调测与实施方案制定的依据。
  - **执行约束（2026-07-29）**：正式基线不在本机工作站（含 WSL）上产生。该机 CPU 为大小核混合架构，MPI 各 rank 落在不同类型核心上性能差异显著，扩展性数据不可比；基线须在 Linux 目标机进行，缺设备按本文件「口径 → 设备」条向浪潮提出。
- [ ] 对现有代码开展性能分析。
  - **已有初步结果（2026-07-28，宋维豪）**：用函数调用热点图分析，结合左上角的 MPI 分配情况，判断**当前并行负载不均衡**。这是性能专项的第一条实质发现，可作为后续调优与「抽取性能基线」的切入点。原始热点图为内部群图片，本仓不留原件。
- [ ] 完成 Hypre、PETSc KSP 迭代法调优与测试，输出性能数据（浪潮方面协助）。
